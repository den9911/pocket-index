# Project notes

The localhost Axum server accepts an explicit folder path and runs a blocking scanner on a worker thread. WalkDir does not follow symbolic links. SQLite FTS5 persists paths, names and text, ranks results and uses the Unicode tokenizer. The previous index is replaced inside one transaction only when the walk and every supported file read succeeds. Read/UTF-8/size failures explicitly roll back the whole candidate; SQL failure drops the transaction. Unsupported extensions and symlinks remain intentional skips. A complete empty folder is a valid new empty snapshot. No accept-partial endpoint is offered. The status reports prepared-file counters separately from the active document count and persisted generation. Search results are inserted into the DOM as text, not HTML; matching terms are marked without interpreting document content as markup.

Limitations: one active index and one build at a time; no stemming, PDF, OCR or file watcher. The local database contains copies of note text. Future work: real screenshots, explicit opt-in partial acceptance as a separate product decision, index selection and Unicode language-specific analysis.

`src/indexer.rs` owns bounded reads, snapshot outcomes and fixed diagnostic reason codes. `pocket_index_state` records generation in the same transaction as FTS rows; old databases start at generation zero without rebuilding documents. Search opens a read-only-in-practice transaction on a separate connection: generation and hits belong to one snapshot. It does not run schema initialization or metadata inserts while the writer is active. WAL readers keep seeing the previous committed index.

A scan observes files as read, not an atomic filesystem snapshot. File reading is capped to MAX_BYTES + 1; unsupported special-file races or indefinitely stalled filesystems are not advertised as fully protected. One process and one rebuild at a time remain the supported model. Existing databases can be reopened by the previous version because FTS schema is unchanged, but older code can again publish partial scans; prefer the repaired version rather than a blind rollback.

Verification: Rust tests cover retained snapshots, bounded growing readers, SQL rollback, WAL readers, metadata upgrade and empty folders. Linux HTTP tests cover actual permission denial, invalid UTF-8, oversized input, missing roots, SQL trigger failure, SIGKILL recovery and retry. Windows/macOS compilation and Rust tests are distinct from manual launcher/browser verification.
